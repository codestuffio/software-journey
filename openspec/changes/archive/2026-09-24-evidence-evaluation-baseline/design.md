## Context

The product now has a pinned OpenSpec snapshot and curated workflow bundle, but lacks a repeatable measure of citation validity and answer quality. See `proposal.md` for the motivation.

## Goals / Non-Goals

**Goals:**

- Evaluate five fixed OpenSpec onboarding questions against local, revision-pinned evidence.
- Produce a small machine-readable local report that distinguishes pass, failure, and unavailable evidence.
- Make evaluation reproducible without a provider, database, or browser checkout access.

**Non-Goals:**

- Scoring model-generated prose, comparing models, or claiming token/cost improvements.
- Automatically generating questions or reference answers.
- Uploading snapshots, bundles, reports, or source excerpts.

## Decisions

### Use a checked-in evaluation catalog

The catalog will contain only authored question text, expected citations, answer-shape criteria, and the pinned OpenSpec identity/revision. Local evaluation reads snapshots and workflow bundles already generated by the user. This keeps the baseline reviewable and avoids treating an evaluator as an inference engine.

### Report evidence outcomes, not narrative quality

The first report will score citation resolution and required evidence availability per case. It will preserve omissions/truncation from inputs and use `unavailable` rather than guessing. Narrative-answer grading is deferred until a provider and rubric are separately specified.

### Keep artifacts bounded and atomic

The evaluator will accept only validated local inputs, limit catalog cases and report size, and atomically write a new output directory outside a checkout. Cancellation cleans temporary output. The CLI and repository package remain the only filesystem/Git boundary; the web interface is unchanged.

## Risks / Trade-offs

- [Five cases are narrow] → Label this a baseline and make catalog expansion a reviewed change.
- [A citation exists but is misleading] → Record citation validity only; defer semantic-answer scoring to a later rubric.
- [Pinned OpenSpec changes] → Reject mismatched inputs and update the catalog only through a new reviewable revision.

## Migration Plan

1. Add contracts, catalog, local evaluator, CLI validation, and focused tests.
2. Produce an ignored OpenSpec report and document the reproducible command.
3. Run the existing verification suite; rollback removes the additive evaluator without changing snapshot or workflow formats.
